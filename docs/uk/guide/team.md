# Командна пам’ять

## Модель

- `.engram/memories.jsonl` — **джерело істини**. Один JSON-запис на рядок, відсортовано за id: записи, зв’язки, сесії та tombstones. Комітьте його.
- `.engram/engram.db` — **локальний SQLite-індекс**, збирається з JSONL. У `.gitignore`.

Кожен запис дзеркалиться в JSONL (атомарно: запис у тимчасовий файл і rename). Під час кожного відкриття engram хешує JSONL; якщо файл змінився з моменту останнього запису — `git pull`, merge, ручне редагування — записи вливаються в локальний індекс.

## Правила злиття

- **Записи:** перемагає останній, хто писав, за `updatedAt`.
- **Tombstones** (жорсткі видалення) перемагають запис, на який вказують.
- **Зв’язки та сесії:** об’єднання.
- **Нерозв’язані git-маркери конфлікту** в JSONL допускаються: обидві сторони вливаються, файл перезаписується начисто.

Файл відсортовано за випадковими id, тож двоє людей, що додають записи, рідко чіпають сусідні рядки — більшість merge проходять без конфліктів.

## Рев’ю того, чого навчився агент

Пам’ять можна рев’юїти як код. Diff pull request’у показує, які рішення та граблі додалися. Читабельне вивантаження:

```bash
engram export --format md -o docs/MEMORY.md
```

## Онбординг

Новий розробник — або новий агент — питає:

> Поясни архітектуру авторизації.

і отримує справжню історію рішень, а не здогадки. `engram summary --full` дає повну картину.

## Приватність

Пам’ять пишеться для колег. Інструкції сервера забороняють агентам зберігати секрети, облікові дані та персональні дані — але рев’юїте `memories.jsonl`, як будь-який закомічений файл. Щоб пам’ять лишалася тільки на вашій машині, додайте `.engram/memories.jsonl` у `.gitignore` або встановіть `"sync": { "jsonl": false }`.
