# Основные понятия

## Записи памяти

Запись — небольшая самодостаточная заметка, написанная для будущего читателя без контекста.

| Поле | Значение |
| --- | --- |
| `id` | Короткий и читаемый: `dec_k3x9q2mf`, `pit_…`, `pri_…` |
| `kind` | Что это (см. ниже) |
| `title` | Конкретный заголовок для поиска — само решение, а не тема |
| `content` | Детали и, главное, **обоснование** |
| `tags` | Темы в нижнем регистре: `auth`, `db`, `payments` |
| `files` | Пути относительно репозитория — для поиска по файлам |
| `status` | `active`, `superseded`, `rejected` или `archived` |
| `importance` | 1 (мелочь) … 5 (несущая конструкция) — влияет на ранжирование и сжатие |
| `source` | `agent`, `user`, `adr:docs/adr/0003.md`, `git:…` |

### Виды (kind)

| Вид | Для чего |
| --- | --- |
| `decision` | Архитектурный или продуктовый выбор — или отвергнутый вариант (`status: rejected`) |
| `pitfall` | Грабли: что случилось, почему, как избежать |
| `principle` | Правило, которое должно соблюдать любое изменение |
| `fact` | Простой факт: «прод-БД — Postgres 16» |
| `discussion` | Суть обсуждения: варианты, аргументы, итог |
| `note` | Всё остальное, что стоит сохранить |
| `file` | Для чего модуль, если это неочевидно из кода |
| `session` | Итог рабочей сессии |

### Дедупликация при записи

Агенты любят «запоминать» одно и то же дважды. Запись с тем же видом и заголовком, что у активной, **обновляет** её (теги и файлы объединяются, важность берётся максимальная).

## Статусы и история

engram не перезаписывает историю, когда вы передумали:

- **superseded** — заменено более новой записью. `supersede(old, new)` помечает старую и добавляет ребро `new —supersedes→ old`.
- **rejected** — вариант рассматривали и отвергли. Именно это делает вопрос «почему не X?» отвечаемым.
- **archived** — мягкое удаление: скрыто из поиска, сохранено для истории. Жёсткое удаление оставляет tombstone, чтобы оно дошло до коллег.

По умолчанию поиск показывает только `active`; `include_inactive` (или `--all`) — всё.

## Граф знаний

Записи соединены типизированными направленными рёбрами:

| Связь | Читается как |
| --- | --- |
| `relates_to` | общая связь |
| `depends_on` | *from* верно, только пока верно *to* |
| `implements` | *from* реализует решение / принцип *to* |
| `supersedes` | *from* заменило *to* |
| `rejected_because` | вариант *from* отвергнут из-за *to* |
| `caused_by` | грабли *from* вызваны *to* |
| `part_of` | *from* — часть большей темы *to* |

`engram_why` проходит по `supersedes`, `rejected_because` и `caused_by` и превращает разрозненные записи в хронологию. `engram_related` ходит по любым рёбрам в обе стороны.

## Сессии

`engram_session_start` открывает сессию под цель и возвращает контекст-пакет. `engram_session_end` сохраняет итог — **сделано / решено / открыто / дальше** — как searchable-запись `session`. Контекст-пакет следующей сессии начинается с неё.

## Контекст-пакет

Компрессор контекста собирает брифинг под задачу в рамках бюджета токенов (по умолчанию 2000):

1. Собираются и приоритизируются **принципы**, **грабли по теме задачи**, **релевантные записи**, **ключевые решения**.
2. Самое приоритетное выводится **целиком**.
3. Следующий уровень **сжимается до одной строки** (id + заголовок + теги).
4. Остальное **отбрасывается** — и пакет сообщает, сколько, чтобы агент знал, что можно сделать `recall`.

## Поиск

Полнотекстовый поиск — SQLite FTS5 с ранжированием BM25 (заголовок ≫ теги > содержимое > файлы), стеммингом Porter и Unicode-токенизацией — работает на английском, русском, украинском и других языках. Затем счёт усиливается по виду, важности, статусу и свежести. Запросы прощают неточности: термины объединяются через OR, длинные ищутся по префиксу — «auth» найдёт «authentication».
